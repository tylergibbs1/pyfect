# Typing experiments

Each file checks one question against pyright. Run one with
`uv run pyright -p research/typing research/typing/<file>` (the project's own
config excludes `research/`; `pyrightconfig.json` here is strict mode without
the exclude). The decisions they led to are pinned by `tests/type_checks.py`.

| File | Question | Answer |
| --- | --- | --- |
| `exp1_tags.py` | Can a tag's identity differ from its shape, with R tracking the tag? | Yes, with `class Primary(Tag[Db])`. A bare class can't be yielded (`yield from Primary`) through a metaclass. |
| `exp2_provide.py` | Can `provide` remove only what a layer builds, leaving the rest of R? | Yes, if the layer is known before the effect: `provide(layer)(eff)`. |
| `exp3_methods.py` | Can `catch_tag` / `provide` be methods? | No. `self` binds first, and `catch_tag` then silently erases *all* errors. Unsound. |
| `exp4_pipe.py`, `exp5_pipe_overloads.py` | Do those work in a multi-step `pipe(a, b)`? | Only the first step narrows; later ones keep the type unchanged. One step per `.pipe()` is exact, so `pipe` takes one function. An exact-match overload is needed so a full match gives `Never`. |
| `exp6_strict.py` | What does strict mode say about unannotated effect generators? | Only that the generator's send type is `Unknown` (pyright #10279). `reportUnknownParameterType = false` silences it; parameters are still required to be annotated. |
| `exp7_layers.py`, `exp8_fixes.py` | Can `layer.succeed(Tag, impl)` check `impl`? Does `E1 \| E2` stay precise? | Recover shape and tag through a protocol on the tag class; make the shape invariant or wrong impls are accepted. Two separate `Never`-defaulted TypeVars in a union become `Unknown`; one shared TypeVar across arguments joins correctly. |
| `exp9_methods_union.py` | Do `flat_map`-style methods hit the same `Unknown`? | Not when they use the class's own TypeVars. Rebinding `self` to fresh TypeVars locks them and rejects valid code. |
| `schema_1_codec.py` | How is Effect's `Codec<T, E, RD, RE>` spelled, and what do decoders, Literal, Union, transformations and brands infer? | `Codec(Generic[T, E = T, RD = Never, RE = Never])`, all covariant; decoders solve all four and a `Never` slot rejects a schema needing services. A `LiteralString` bound keeps string literals (all-int calls widen to `int`). One shared TypeVar set joins Union members. A curried function returning a *generic* `Callable` is not checked by `.pipe`: use a class with a generic `__call__`. A `NewType` matched against `Callable[[A], B]` gives `Any`, so brands name both types (`Brand[str, UserId]`). |
| `schema_2_struct.py` | How should a struct be declared so pyright infers it? | Schema types as annotations through descriptors (`id: S.Int`) infer the Type but need a type-level twin of every schema. Plain annotations (`id: int`) give the Type for free; a field specifier `score: float = S.field(S.NumberFromString)` is checked against the annotation. No spelling gives a struct's Encoded (no mapped types): it is `Mapping[str, object]`. A TypedDict gives an exact Struct Type, `NotRequired` included. |
| `schema_3_protocol.py` | Can one parameter type take schema values and schema classes? | Yes: a `Codec` protocol with one member, `__codec__`, matched by schema objects (returning themselves) and by classes (a classmethod returning `Bottom[Self, Mapping[str, object]]`). |
| `schema_4_tagged.py` | Can a tagged union of TypedDicts be matched exhaustively, and can `NewType` make a struct nominal (Effect's `Opaque`)? | A `match` on `{"_tag": "A"}` mapping patterns narrows each TypedDict and `assert_never` catches a missing case (not when the pattern also captures a key; class patterns may capture). `NewType` of a TypedDict is rejected and a TypedDict subclass stays structural, so `Opaque` is `S.Class`. |
| `schema_5_extra_items.py` | Can pyright type Effect's `StructWithRest`? | Yes, through PEP 728: `TypedDict(..., extra_items=float)` (from `typing_extensions` before Python 3.15) types the undeclared keys and rejects a wrong one. |
| `cli_1_config.py` | How should a CLI command's config be declared so the handler's input is inferred? | A class of params read through `__get__` (`repository = Argument.string("repository")` gives `str`; `optional()` gives `A \| None`); nested groups through a descriptor over another config class. `yield from parent` types the shared flags and adds `CommandContext[Shared]` to R, which `with_subcommands` removes by union matching; handlers lose the built-in `LogLevel` tag. The command type must be invariant in its input, or `with_shared_flags`'s exact overload for an empty config matches every config. |
| `httpapi_1_endpoint.py` | How should an HttpApi endpoint be declared so the handler's request and the derived client are exactly typed? | `Endpoint[P, Q, B, H, S, E]`, one decoded type per slot, `None` for an absent one (function TypeVar defaults). A group is a class of endpoints; read on an instance, an endpoint is the client method (`__get__` overloads), whose `self`-typed `__call__` overloads take exactly the declared keywords. `S` and `E` must be invariant, or the handler's wider success or error is accepted. |
| `httpapi_2_middleware.py` | Can middleware add its error and remove the service it provides from a handler? | Yes, with the handler in a second call, `handle(endpoint)(fn)`: union matching removes `MP` only when it is fixed before the handler is seen. Group-level middleware is the group class's type argument, read back by the descriptor; a group without middleware needs its own first overload. |
| `workflow_1_schemas.py` | How should a workflow and an activity be declared so payload, success and error come from their schemas? | `make(payload=, success=, error=)` solves `Workflow[P, A, E]`; overloads on a keyword-only `discard: Literal[True]` give `execute` its two results; union matching removes `WorkflowEngine \| WorkflowInstance \| Scope` from a handler's requirements. Covariant schema and effect parameters widen an activity's `A` (no `NoInfer` in 3.13). |
| `workflow_2_exact_schemas.py` | Does fixing `A` from the schema hold in either argument order, and what does a handler needing nothing infer? | Pyright solves arguments in the order written, so an invariant protocol over `__codec__() -> Bottom[T]` still widens when `execute=` comes first. `Exactly[T]`, whose `__codec__` returns something with `make(input: T) -> T`, pins `T` either way (services go unchecked). A handler needing nothing leaves `R` `Unknown`; a first overload without the TypeVar gives `Never`. `layer.merge` of layers that all build `Never` builds `Unknown`. |
| `ai_1_toolkit.py` | Can a toolkit's tool names, parameters, results and failures, and `generate_object`'s schema type, flow into `generate_text` / `generate_object` results? | Yes. `Tool[N, P, S, F, HE, R]` with covariant TypeVars (`*_co`); a toolkit is `Toolkit[N1 \| N2, ...]` built by `make` overloads (0-4 tools plus a variadic fallback), and its result parts are a union of `ToolResultSuccess[N, S] \| ToolResultFailure[N, F]` that a `match` on `name` / `is_failure` narrows. `tool.handler(fn)` checks `fn`'s success against `S` and its error against `F \| AiError`; `to_layer` gives `Layer[Handlers[N]]`, which `generate_text` requires. Optional schema parameters must be `Codec[...] \| None = None` with TypeVar defaults: an `= ...` default leaves the TypeVar unsolved. |
| `model_1_variants.py` | Can a `Model.Class`'s variants be inferred from its fields, and can a repository's `insert` / `update` / `find_by_id` take and return the right variant? | Not inferred: no mapped types, so no spelling projects a class onto one variant's keys. Declared instead: `Model.Class[Insert, Update, Json, JsonCreate, JsonUpdate]` takes TypedDicts (defaulting to `Mapping[str, object]`), read back through non-data descriptors whose `__get__` solves the owner's type arguments (`User.insert` is `VariantStructSchema[UserInsert]`), checked against the fields when the class is made. A `__model_variants__` classmethod returning `ModelVariants[Self, I, U]` lets `make_repository(User, ...)` solve `Repository[User, UserInsert, UserUpdate]`. A field the select variant lacks is assigned without an annotation (no dataclass field). The id type cannot come from a column name. A base class expression of type `type[X]` (a toolkit's `Class`) keeps `dataclass_transform`. |
| `graphql_1_client.py` | Can a GraphQL group's operations be typed client methods whose errors and services include their middleware's and their group's, and can `make` read the group's middleware tags? | Yes. An operation is `Operation[V, A, ME, MR]` (one services parameter: `R \| MR` of two class TypeVars that are both `Never` is `Unknown`); `op.middleware(Tag)` solves `E` and `R` through `TagLike[Implementation[E, R], T]`. A group is a class `GraphQLGroup[M1 \| M2]`; the descriptor's `__get__` overloads (`GraphQLGroup[Never]` first, then `GraphQLGroup[GraphQLMiddleware[GE, GR]]`) add the group's middleware on an instance (the client method) and on the class (so another group takes the operation with it, Effect's `merge`). `make(Group)` solves the client and the middleware tags from a `__graphql_group__` classmethod returning `GroupTypes[Self, GM]`. `partial: Literal[True]` overloads and a `NoVariables` self-type give the four call forms; `pages` / `items` read connections through `ReadOnly` TypedDicts. Known gap: a middleware attached to one operation is not in `make`'s requirements (only group middleware is). |
