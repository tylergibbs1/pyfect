description: "Acquire and release resources safely with scopes, and share them with caches, pools and maps."

A **scope** collects finalizers and runs them when it closes. `fx.acquire_release` acquires a
resource and registers its release on the current scope; its type then includes `Scope`, and
`fx.scoped` provides a scope that closes when the effect ends.

<include meta='title="acquire_release.py"'>../../snippets/resources/acquire_release.py</include>

The release runs whether the effect succeeds, fails or is interrupted, and acquisition can't be
interrupted halfway. Finalizers run in reverse order of acquisition.

## In layers

A layer built with `layer.effect(Tag, acquire_release(...))` owns its resource: it is acquired
when the layer is built and released when the program using it ends. This is how a connection
pool lives for a whole program (see `examples/fastapi_style.py` in the repository).

## Caching lookups

`fx.Cache.make(lookup, capacity=..., time_to_live=...)` runs `lookup(key)` the first time a
key is asked for and shares the outcome with every later caller, including callers that ask
while the lookup is still running. The least recently used entries go first once there are
`capacity` of them, and an entry expires after its time to live. A `time_to_live` function
that raises ends that lookup with the error as a defect, for every caller waiting on it, and
keeps nothing.

<include meta='title="cache.py"'>../../snippets/resources/cache.py</include>

`ScopedCache` is the same for lookups that hold resources: each entry's resources are
released when it leaves the cache.

## Pooling connections

`fx.Pool.make(acquire, size=...)` acquires `size` items with a scoped effect and lends them
out: `pool.use(f)` borrows one for as long as `f`'s effect runs, and borrowers wait in line
for a free one. All the items are released when the pool's scope closes.
`Pool.make_with_ttl(acquire, min=..., max=..., time_to_live=...)` grows with demand and
shrinks back once items have been idle. `pool.stats()` gives a `PoolStats` snapshot (idle and
used items, waiting borrowers, `min` and `max`) to report as metrics.

## Sharing by key

`fx.RcMap.make(lookup)` acquires `lookup(key)` for the first scope that asks for a key and
shares it with every other scope that asks while it is held. When the last one closes, the
resource is released, at once or after `idle_time_to_live`. `RcRef` is the same for a single
resource.

<include meta='title="rc_map.py"'>../../snippets/resources/rc_map.py</include>

`fx.LayerMapService` does this for whole layers: `Greeters.layer(lookup)` builds
`lookup(key)` the first time `Greeters.get(key)` is provided, and shares its services while
they are in use. It suits a service per tenant, or per model.

<include meta='title="layer_map.py"'>../../snippets/resources/layer_map.py</include>

`LayerMapService[K, I, E]` takes a third type parameter, what a lookup's layer can fail
with; `get(key)` is then a layer failing with it. It defaults to `Never`.

<Callout title="Make a per-key layer in the lookup, not in a constant">

A `LayerMap` builds every key's layer with one shared memo map, as Effect's does, so a layer
object is built once while any key holds it. A [module-level layer
constant](/docs/services) used inside the lookup is one object: with `idle_time_to_live`,
the keys built while the first one is held all get its build, so tenant `globex` reads
`acme`'s database. Without a time-to-live it only shows when two keys are in use at once.
Make anything that depends on the key inside the lookup function, so each key gets its own
layer.

</Callout>

## Swapping and refreshing

`fx.ScopedRef.from_acquire(acquire)` holds a value with resources. `set(acquire)` acquires
the next value, then releases the one it replaces, and keeps the current one if acquiring
fails.

<include meta='title="scoped_ref.py"'>../../snippets/resources/scoped_ref.py</include>

`fx.Resource.manual(acquire)` caches what `acquire` gives; `get` reads it and `refresh`
acquires anew. `Resource.auto(acquire, schedule)` refreshes it on a schedule.
