A `Stream[A, E, R]` emits any number of `A`s, then ends or fails with `E`. Streams are pulled:
nothing runs until a consumer asks for items, so a slow consumer slows the producer down
(backpressure) and memory stays bounded.

Build streams with `stream.make`, `from_iterable`, `range`, `unfold`, `paginate`,
`from_queue`, `from_async_iterable`, `tick`, ... and transform them with methods: `map`,
`map_effect`, `filter`, `take`, `scan`, `grouped`, `zip`, `merge`, `buffer`, `debounce`,
`throttle`, `retry`, `timeout`. The ones that remove an error or a service (`stream.catch_tag`,
`stream.provide`) are functions for `.pipe`, as for effects.

## Sinks

A `Sink` consumes a stream and produces a result; `run_collect`, `run_fold` and
`run_for_each` are shortcuts for common ones.

## Batches

`grouped(n)` emits lists of `n` items. `grouped_within(n, duration)` also ends a batch once
`duration` has passed since its first item, so a burst goes out in full batches and a
straggler is not held back waiting for more. Here a queue's items are posted three at a time.

## A pipeline

NDJSON records arriving in byte chunks, priced by a flaky service four at a time with retries,
buffered so memory stays bounded, batched and written by a sink. `examples/stream_pipeline.py`
in the repository is a longer version.

<include meta='title="pipeline.py"'>../../snippets/streams/pipeline.py</include>

Streams are pulled: nothing upstream runs until the sink asks for more. `map_effect` keeps
at most four calls in flight and `buffer` lets pricing run at most eight items ahead of the
writer, so a slow sink slows the whole pipeline instead of filling memory.

## SchemaBinary

`pyfect.encoding.schema_binary` writes a schema's values as compact binary frames, with the
same bytes as Effect's `encoding/SchemaBinary`. `to_codec(schema)` is a schema from `bytes`
holding one frame. `parser(schema)` reads concatenated frames from chunks split anywhere, and
`encoder(schema)` writes them, with a string dictionary for a connection when given
`dictionary=True`. `encode(schema)`, `decode(schema)` and `duplex(channel, input_schema=...,
output_schema=...)` are the same as channels for `Stream.pipe_through_channel`.

<include meta='title="schema_binary.py"'>../../snippets/streams/schema_binary.py</include>

<include lang="text">../../snippets/streams/schema_binary.out</include>

Field ids are hashes of their names, so renaming a field changes its wire identity:
`S.String.pipe(schema_binary.field_id(7))` fixes it across a rename. `S.field(S.String, key="primaryKey")`
gives a snake_case attribute Effect's camelCase field, on every wire. A `datetime` is written
in whole milliseconds. Python has no infinite `timedelta` and its dates cover years 1 to 9999,
so Effect's values beyond those fail to read here.

Reference: [`pyfect.stream`](/docs/reference/stream), [`pyfect.sink`](/docs/reference/sink),
[`pyfect.channel`](/docs/reference/channel),
[`pyfect.encoding.schema_binary`](/docs/reference/encoding/schema_binary).

## XML

`pyfect.encoding.xml` reads a document as a stream of events, so a large one never has to fit in
memory. `decode_string()` takes text and `decode()` takes UTF-8 bytes. `elements(path)` turns events
back into one small tree per record, and `encode_string()` and `encode()` write events out.

<include meta='title="xml_feed.py"'>../../snippets/streams/xml_feed.py</include>

<include lang="text">../../snippets/streams/xml_feed.out</include>

A reference to any entity but the predefined ones fails with an `"Unsupported"` error instead of
being expanded, so a document cannot read local files or expand into gigabytes. `max_token_size`, `max_depth` and
`max_element_size` bound what one document can hold in memory.

## Zip and tar

`pyfect.encoding.zip` and `pyfect.encoding.tar` read an archive as a stream of entries, each with a
header and a `body` stream, and write entries back to archive bytes. Bodies are streamed in both
directions, so an archive does not have to fit in memory.

<include meta='title="archives.py"'>../../snippets/streams/archives.py</include>

<include lang="text">../../snippets/streams/archives.out</include>

Read each body before pulling the next entry: a later read fails with `"BodyConsumed"`, and pulling
the next entry skips what is left. `map_effect` is the usual way to do that.

Neither decoder touches the file system, and both return paths as written in the archive. As in
Effect, a path can be absolute or contain `..`, a tar symlink can redirect the entries after it, and
a zip's central directory is not read, so other tools can see different entries. A deflated zip body
can also expand about a thousand times. Before writing entries to disk, reject paths that leave the
target directory and limit how many bytes you read:
