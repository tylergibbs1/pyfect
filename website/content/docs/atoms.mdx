An atom is a recipe for a value: a constant, a function of other atoms, an effect or a
stream. An atom holds nothing itself. A registry builds the atoms you read, keeps their
values while something uses them, and rebuilds an atom when an atom it read changes.
`pyfect.reactivity` follows Effect's `effect/reactivity`: `atom`, `atom_registry`,
`atom_rpc`, `atom_http_api` and `hydration` are submodules of it.

## Atoms and derived atoms

`atom.make(1)` is a writable atom holding `1`. `atom.make(lambda get: get(count) * 2)` is a
derived atom: `get` reads another atom and records it as a dependency, so setting `count`
rebuilds `doubled` and notifies its subscribers. `atom.family(f)` gives one atom per key,
compared with `Equal`, so `todo(1)` is the same atom each time it is called.

`atom_registry.make()` creates a registry on the running fiber's scheduler.
`registry.get`, `set`, `update` and `subscribe` work on it directly, and `subscribe`
returns the function that unsubscribes. An atom that no subscriber, mount or other live
atom uses is removed from the registry, and built again when it is read next;
`keep_alive()` keeps it, and `set_idle_ttl(seconds)` keeps it for a while after its last
use. Methods like `map`, `with_fallback` and `debounce` derive a new atom from one.

## Effect and stream atoms

An atom made from an effect holds an `AsyncResult`: `Initial` while the effect runs, then
`Success` or `Failure`. The registry runs the effect when the atom is built and interrupts
it when the atom is removed. A stream atom holds a result of the stream's latest item.
`atom.fn(f)` is a function atom: writing an argument to it runs `f(arg, get)`, and a new
write interrupts the run in progress. `atom.runtime(layer)` builds a layer once per
registry, and its `atom` and `fn` make atoms whose effects use that layer's services.

The effects `atom.get`, `atom.set` and `atom.get_result` use the registry that
`atom_registry.layer` provides. `get_result` waits for an atom's first `Success` or
`Failure`, and with `suspend_on_waiting=True` for one that is not still running.

## RPC and HTTP API atoms

`atom_rpc.make(Tag, group=..., protocol=...)` turns an [RPC](/docs/rpc) group into atoms.
`client.query(rpc, payload)` is an atom of the call's result, one per payload, and
`client.mutation(rpc)` a function atom taking a `MutationRequest`. A query's
`reactivity_keys` tie it to the mutations that change it: a mutation written with the same
keys refreshes those queries once it succeeds. A query also takes `headers`,
`time_to_live` and a `serialization_key` for hydration.

## Hydration

`atom.serializable(key=..., schema=...)` marks an atom whose value can leave the process.
`hydration.dehydrate(registry)` encodes the serializable atoms a registry holds, and
`DehydratedAtom.to_json()` writes each entry as Effect does, so a Python server can hand
state to an Effect client and back. `hydration.hydrate(registry, entries)` preloads another
registry by key before its atoms are read. An effect atom still runs once it is built
unless it is marked `skip_initial_run=True`, which keeps the hydrated value until the
atom is refreshed or a dependency changes. `async_result.Schema` encodes an `AsyncResult`
the way Effect's `AsyncResult.Schema` does.
