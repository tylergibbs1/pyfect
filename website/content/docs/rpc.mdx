---
title: RPC
description: "Typed remote procedure calls over HTTP or WebSockets, with streaming results."
---

An `RpcGroup` declares procedures: each has a tag, and the schemas of its payload, success
and error. The server runs a handler per procedure; the client is an instance of the group
whose attributes call them, typed by the same schemas. Calls are messages, so one connection
carries many at once, and a procedure can answer with a stream of values.

<Diagram name="rpc-call" title="A call sends a Request through the protocol to the server's handler; the answer comes back as an Exit, after a Chunk for each batch of a stream's values" />

## Define, serve and call a group

`rpc.make(tag, payload=..., success=..., error=...)` declares a procedure; a success of
`rpc_schema.Stream(values, error)` makes it a stream. `Group.handlers().handle(Group.rpc)(f)`
adds a handler, which takes an `RpcRequest` with the decoded `payload` and gives the success
value (or a `Stream` of them) or fails with the declared error. `Group.to_layer(handlers)` is
their layer, and raises `ValueError` naming each procedure left without a handler.

A group can list its tags, `class Users(RpcGroup[Literal["GetUser", "Users"]])`, so pyright
checks its handlers as TypeScript checks Effect's `toLayer`: `to_layer` rejects them while a
procedure has none, and a second handler for one is an error. Python has no way to gather a
class's attributes into a type, so the list repeats the tags; the class is checked against it
when it is defined, and a `TypeError` names any tag missing from either side. A tag must be a
string literal at `rpc.make` for its procedure to be checked (`prefix` makes it a plain
`str`).

`rpc_server.layer_http(Group, path=...)` serves the group on a route of the
[router](/docs/http-server), over WebSockets by default or HTTP POSTs with
`protocol="http"`. A call or handshake from a browser page of another origin is refused
with 403; `layer.succeed(AllowedOrigins, origin.allow("https://app.example"))` (from
`pyfect.http.origin`) lists the origins to accept too. Messages are encoded by the
`RpcSerialization` in the context:
`serialization.layer_ndjson` or `layer_json`, JSON-RPC 2.0 with `layer_json_rpc()` and
`layer_nd_json_rpc()`, or `layer_schema_binary()`, the
[binary format](/docs/streams#schemabinary), whose frames read and write the same bytes as
Effect's (`max_frame_size=` limits a frame, 16 MiB by default; `fingerprint_payloads=True`
fails on a payload whose layout differs). `router.serve` passes the layer's needs through, so the handlers
(`HandlersFor[Group]`) and the serialization can be provided to the served layer.

`rpc_server.layer_protocol_stdio` serves a group over standard input and output, for a
program another one starts: `rpc_server.layer(Group)` over it, launched, ends once input has
ended and the last response is written. As in Effect, the end interrupts the fiber that built
the layer, so under `run_main` the program exits with status 130, not 0.

`rpc_client.make(Group)` is the client, over the `ClientProtocol` in the context:
`layer_protocol_http(url)` sends calls as POSTs, and `layer_protocol_socket()` over the
`Socket` in the context. A call fails with the procedure's error or an `RpcClientError`,
whose `reason` is the socket's or worker's error, an `HttpClientErrorSchema` for an HTTP
failure, or an `RpcClientDefect`; it is a schema class, so it encodes as Effect's does;
a stream procedure gives a `Stream`. `client.rpc.discard(payload)` completes once the
server acknowledges the call as its handler starts, after the middleware ran: the handler's
result is not returned, but a middleware error or a failure before the handler starts still
fails it (over HTTP and workers it completes when the handler is done).

A JSON-RPC notification (a request without an `id`) runs like any call but gets no reply; one
for an unknown method or with an invalid payload is dropped and logged at debug level.
`layer_json_rpc(control_messages=False)` reads `@effect/rpc/*` methods as ordinary
notifications, for plain JSON-RPC peers. `ServerOptions(on_disconnect=...)` is called with
each client id the transport reports disconnected, after its requests were interrupted.

The client is valid while the protocol is. Provide the protocol around the code that uses
the client, or pass it as `rpc_client.make(Group, layer=protocol)`, which builds it into the
caller's scope. `rpc_client.make(Group).pipe(fx.provide(protocol))` releases the protocol
(and its WebSocket) as soon as the client is made; every call on that client then fails
with an `RpcClientError` saying the protocol is closed.

### Over a WebSocket

`pyfect.socket.ws.layer_web_socket(url)` is a client `Socket` on the `websockets` library,
installed with the extra: `pip install "pyfect-dev[websockets]"`. Under
`layer_protocol_socket()` it gives a protocol that sends every call over one connection,
reconnecting when it drops.

current user.

## Security defaults

- A WebSocket handshake or HTTP call from a browser page of another origin gets a 403 unless
  `AllowedOrigins` lists it.
- Headers the transport carries, such as those of the HTTP request or the WebSocket
  upgrade, win over headers of the same name inside a message, so a client cannot claim a
  header that a proxy or gateway set. A message's headers must be string pairs; any other
  shape fails only that request. An object of strings is read only on a transport that
  carries no headers of its own (standard input and output, workers): over HTTP or a
  WebSocket the transport's pairs come first, as in Effect, and an object can't follow them.
- The client checks every message from the server before routing it, so a frame that isn't
  a message fails the waiting call with an `RpcClientError` and the connection keeps
  working. An `Exit` that doesn't decode with the procedure's schemas is a defect of the
  call holding the `SchemaError`, as in Effect. Closing a client's scope sends an Interrupt for each call still running and drops
  late replies for it.

## Testing handlers

`pyfect.rpc.test.make_client(Group, layer=GroupLive)` calls the handlers in memory,
without a server or serialization. The layer is built into the test's scope, so a database
or forked workers in it stay open while the client is used; provided to `make_client(...)`
alone, it would be released once the client is made.

To test over real HTTP against `uvicorn_server.layer_test()`, give
`rpc_client.layer_protocol_http` a real client and the absolute URL from
`server.address_formatted_with`. The test server's own `HttpClient` doesn't work here, in
Effect either: it prefixes every URL with the server's origin, then the protocol prefixes
its URL on top. A relative URL fails with `InvalidUrl` (`POST /rpc/http://127.0.0.1:PORT/`)
and an absolute one with `Error decoding HTTP response`.
