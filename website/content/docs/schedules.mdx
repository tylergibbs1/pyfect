A **schedule** decides whether to try again and how long to wait. `retry` uses one to re-run an
effect after a failure; `repeat` re-runs it after a success.

`retry` and `repeat` take a schedule, or the keywords `schedule=`, `times=`, `while_=` and
`until=`. When retries run out, the effect fails with the last error.

<include meta='title="repeat.py"'>../../snippets/schedules/repeat.py</include>

Constructors: `spaced`, `fixed`, `exponential`, `fibonacci`, `windowed`, `recurs`, `cron`.
Combinators: `up_to(times=, duration=)`, `jittered`, `while_`, `max` / `min`, `concat`, and
more. They are methods; `jittered` and `passthrough` also pipe (`s.pipe(schedule.jittered)`). Schedules use the `Clock` service, so tests can run them on virtual time
([Testing](/docs/testing)).

## Cron

`pyfect.cron` parses cron expressions: five fields (minute, hour, day, month, weekday), or
six with seconds first, in a time zone. `cron.next(c, now)` is the first matching time after
`now`, `cron.sequence` the ones after it, and `cron.match` tests a datetime. `cron.parse`
returns a `Result` with a `CronParseError` for a bad expression; `cron.parse_unsafe` raises
it. `schedule.cron` repeats an effect at each matching time. To run a cron job once across a
cluster, see [cron jobs](/docs/cluster#singletons-and-cron-jobs).
