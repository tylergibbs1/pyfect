A **schedule** decides whether to try again and how long to wait. `retry` uses one to re-run an
effect after a failure; `repeat` re-runs it after a success.

`retry` and `repeat` take a schedule, or the keywords `schedule=`, `times=`, `while_=` and
`until=`. When retries run out, the effect fails with the last error.

Constructors: `spaced`, `fixed`, `exponential`, `fibonacci`, `windowed`, `recurs`, `cron`.
Combinators: `up_to(times=, duration=)`, `jittered`, `while_`, `max` / `min`, `concat`, and
more. They are methods; `jittered` and `passthrough` also pipe (`s.pipe(schedule.jittered)`). Schedules use the `Clock` service, so tests can run them on virtual time
([Testing](/docs/testing)).

## Durations

Every duration in pyfect (a sleep, a timeout, a schedule's delay, a time to live) takes a string
with its unit (`"500 millis"`, `"10 seconds"`, `"1 hour"`), a `timedelta`, a `(seconds, nanos)`
pair, a mapping such as `{"minutes": 1, "seconds": 30}`, or a bare number of milliseconds, as in
Effect (the type is `duration.Input`). An invalid string raises `ValueError`.

Each one is parsed once, at the boundary, into a `duration.Duration`: Effect's `Duration`, an
immutable value of whole milliseconds, whole nanoseconds or an infinity. It stays exact past what
a float can count, adds and compares with other durations (not with numbers), and gives units back
with `to_millis()`, `to_seconds()`, `to_nanos()`, `to_timedelta()`, `format()` and
`format_iso()`. A schedule's delay and `timed`'s result are durations too; a schedule step's
`elapsed` is milliseconds, as in Effect.

## Cron

`pyfect.cron` parses cron expressions: five fields (minute, hour, day, month, weekday), or
six with seconds first, in a time zone. `cron.next(c, now)` is the first matching time after
`now`, `cron.sequence` the ones after it, and `cron.match` tests a datetime. `cron.parse`
returns a `Result` with a `CronParseError` for a bad expression; `cron.parse_unsafe` raises
it. A wall time a DST change repeats runs at its first occurrence;
`on_dst_overlap="later"` picks the second and `"both"` runs at both (`cron.parse(expr, tz,
on_dst_overlap=...)`, also on `schedule.cron`). `schedule.cron` repeats an effect at each
matching time. To run a cron job once across a
cluster, see [cron jobs](/docs/cluster#singletons-and-cron-jobs).

A zone is named the way `Intl` names it in Node, which is how Effect's `DateTime` names it:
with ICU's canonical id, read from ICU 78.3 (Node 24.22.1). ICU keeps the older name of a
renamed zone, so `date_time.zone_named("Asia/Kolkata")` is `Asia/Calcutta`, `EST` is
`America/Panama`, `Etc/UTC` is `UTC` and `+0530` is `+05:30`; an id ICU doesn't know gives
`None`.

## Formatting dates

`date_time.intl` is Effect's `DateTime.format`, `formatUtc` and `formatLocal`, which print
what `Intl.DateTimeFormat` prints under Node. `format` writes a datetime in its own zone,
`format_utc` in UTC (even with a `time_zone`, as Effect's does) and `format_local` in the
system's zone or `time_zone`. The options are `Intl`'s: `date_style` and `time_style`, or the
fields `weekday`, `year`, `month`, `day`, `hour`, `minute` and `second`; mixing a style with a
field is a `TypeError`, as in `Intl`. With no `locale`, or one ICU lacks, the locale is the
environment's (`LC_ALL`, `LC_MESSAGES`, `LANG`), as Node's is.

The text is Node's because the work is Node's, ported: V8's option handling, ICU's pattern

calendars, reading the data ICU ships. That data is pinned to one Node: ICU 78.3 and the
CLDR 48.0 release it is built from, as Node 24.22.1 has them, with ICU's metazone table for
tz 2026e. A Node with another ICU can print other text for the same date (CLDR changes names
and patterns between releases), so the pin moves only with a regenerated data file
(`scripts/gen_intl_cldr.py`) and regenerated answers (`scripts/gen_intl_answers.py`), and
`tests/oracle/test_intl_differential.py` checks over 33,000 cases against that Node's
answers.

One known difference remains, and the test checks it still differs:

- **calendar not ported**: a locale asking for a calendar other than Gregorian, Buddhist and
  Persian with `-u-ca-` (`ja-JP-u-ca-japanese`, `ar-SA-u-ca-islamic-umalqura`,
  `he-IL-u-ca-hebrew`, `zh-CN-u-ca-chinese`, `en-US-u-ca-roc`, `am-ET-u-ca-ethiopic`,
  `hi-IN-u-ca-indian`) raises `ValueError`, where `Intl` formats in that calendar. No locale's
  default calendar is one of them.
