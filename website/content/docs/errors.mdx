---
title: Typed errors
description: "Expected failures in the type, handled with catch_tag; defects kept apart."
---

pyfect separates two kinds of failure, as Effect does:

- **Failures** are expected: a user is not found, a request times out. They are values of the
  error type `E`, and the type tells callers which ones to handle.
- **Defects** are bugs: a `ZeroDivisionError`, a broken invariant. They are not in the type and
  ordinary handlers don't see them.

## Defining and failing

Subclass `fx.TaggedError`; an error with fields must be a `@dataclass` (constructing one
whose fields nothing sets raises `TypeError`), while `S.TaggedError` needs no decorator. Inside a generator, yielding an error fails
the effect: `return (yield from NotFound(key))`. Outside one, use `fx.fail(error)`.

## Handling errors

`catch_tag(ErrorClass, handler)` handles one error class and removes it from the type. Because it
removes something, it is a function you use with `.pipe(...)`, one per call; pyright cannot infer
the removal from a method. `catch_all` handles every typed error, as a method or, for `.pipe`,
`fx.catch_all(handler)` with a typed `def` as the handler: pyright checks the curried call before
`.pipe` supplies the effect, so a lambda's parameter would be `Unknown`. The same goes for
`or_else=` of `catch_tag` and `catch_if`.

Other handlers: `catch_if`, `map_error`, `or_else_succeed`, `match`, `result` (an
`Ok`/`Err` value), `ignore`, and `retry` (see [Schedules and retries](/docs/schedules)).

## Defects

An exception raised inside `fx.sync` or a `map` is a defect. Use `fx.try_` (or `try_async`,
`try_blocking`) with `catch=` to turn an exception you expect into a typed failure.

When a failure and a defect happen together (a finalizer crashed while handling an error),
the defect wins and typed handlers don't run, so a bug is never mistaken for a handled error.
A failed run's `Exit` holds a `Cause`; `cause.pretty()` prints every failure, defect and
interruption in it with tracebacks.

## Reading a failed Exit

`fx.run_blocking_exit` gives an `Exit`: `Success(value)` or `Failure(cause)`. To get the typed error
out of a cause, `cause.find_error()` returns `Ok(error)` for the first typed error, or `Err` of
the cause when it holds none (a defect or an interruption). `cause.find_fail()` returns the `Fail`
reason itself, whose `.error` is the error, or the cause when it holds none. In tests, `testing.assert_exit_fail(exit, error)`
checks a failure by its error (see [Testing](/docs/testing#checking-failures)).
