The [Model Context Protocol](https://modelcontextprotocol.io) lets an AI application use
tools, resources and prompts that another program serves. `pyfect.ai.mcp_server` serves
them from the same [toolkits](/docs/ai#tools-and-toolkits) a `LanguageModel` uses, and
`pyfect.ai.mcp_client` connects to any MCP server. Both speak the protocol's revisions
from 2024-11-05 to the stateless 2026-07-28.

## Serve a toolkit

`mcp_server.toolkit(Calculator)` registers a toolkit's tools, with its handlers' layer
provided. Each tool is listed with its description, its parameters' JSON Schema and an
output schema; `tool.Readonly`, `Destructive`, `Idempotent` and `OpenWorld` annotations
become its hints. Invalid arguments and declared failures come back as tool errors the
model can read, and any other failure as an internal error that leaks no details. The
2025 revisions allow only an object as a structured result, so a tool whose result is
another kind of value, such as a list, sends it as `{"result": ...}`, with an output
schema saying so; pyfect's client unwraps it.
`mcp_server.resource`, `resource_template` and `prompt` add resources and prompts the same
way, as layers.

A transport layer serves them. `mcp_server.layer_http(name=..., version=..., path=...,
protocols=...)` adds MCP's Streamable HTTP transport to an
[HTTP router](/docs/http-server), with sessions and JSON or Server-Sent Event replies.
`mcp_server.run_stdio(...)` serves on standard input and output until the input ends, for
a server that a client starts as a child process; see
[`examples/mcp_server.py`](https://github.com/tylergibbs1/pyfect/blob/main/examples/mcp_server.py).

## Connect a client

`mcp_client.layer_http(name=..., version=..., url=..., protocol=...)` connects to a server
over HTTP, and `layer_stdio(command=process.make(...), ...)` starts one as a child process.
The `McpClient` then has the server's `server_info` and `instructions`, `list_tools`,
`list_prompts` and `list_resources`, `call_tool(tool, arguments, schema=...)` decoding the
result's structured content, `get_prompt` and `read_resource`. Failures are an
`McpClientError` whose `reason` says which: a tool error, a timeout (60 seconds by
default), a transport or protocol error.

`mcp_client.toolkit(client, prefix)` gives the server's tools as a toolkit with their
handlers, so `generate_text(prompt, toolkit=...)` lets a model call another program's
tools. Each model tool is named `prefix` followed by the server's name for it, joined as
they are, as in Effect: `"docs__"` gives `docs__search`, and `"docs"` gives `docssearch`.
A tool error from the server (`isError`) fails the call with `McpClientError` by default.
Pass `failure_mode="return"` to give it to the model as a failed result instead, as a
local tool with `failure_mode="return"` does, so the model can read "no country has the
code 'XX'" and answer. A request that fails, such as a timeout or a closed transport, then
goes back to the model too, as its error message.

Each request is a span on both sides, named for its method: `McpClient.tools/call` on
the client and `McpServer.tools/call` on the server, each with a `tool` attribute, inside
the trace of the HTTP request that carries it.

## Security defaults

- `mcp_server.layer_http` keeps at most `max_sessions` (1000) sessions and answers 503 when
  they are all in use; a session idle for `session_idle_timeout` (30 minutes) expires. A
  message larger than `max_message_bytes` (4 MiB, and never more than the app's
  `MaxBodySize`) gets a 413.
- A defect in a tool, resource, prompt or completion handler is logged and the client gets
  "Internal server error"; a declared failure sends its message, never its fields.
- Replies to the server's own requests (roots, sampling, elicitation) are decoded with their
  result schema; a malformed elicitation reply counts as declined.
- The client reads each server message under `max_message_bytes` (16 MiB by default) and
  fails with a `LimitError` reason past it. JSON nested too deeply to parse is a parse
  error on both sides, not a crash.
