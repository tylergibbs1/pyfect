## Logging

`fx.log_info(...)`, `log_debug`, `log_warning`, `log_error` write to the loggers in
`CurrentLoggers`, skipping entries below `MinimumLogLevel` (`INFO` by default). Annotations and
log spans add context to every entry inside an effect.

<include meta='title="log_entries.py"'>../../snippets/observability/log_entries.py</include>

`logger.layer([...])` replaces the loggers: `console_pretty`, `console_logfmt`, `console_json`,
`batched(...)`, your own `fx.Logger.make(...)`, or `logger.to_logging("app")` to hand entries to
the standard library's `logging`.

## Tracing

`eff.with_span(name)` runs an effect inside a span; `@fx.fn("name")` does the same for every call
of a function. Spans nest across forked fibers, and logs inside a span become its events.

<include meta='title="tracing.py"'>../../snippets/observability/tracing.py</include>

The native tracer keeps spans in memory. To export them, install the OpenTelemetry bridge
(`pyfect-dev[otel]`) and provide `otel.sdk.layer(otel.sdk.Configuration(...))`. Its
`resource` names the service; each signal is on once it has somewhere to go: spans with a
`span_processor`, metrics with a `metric_reader`, logs with a `log_record_processor`. The
providers flush and shut down when the layer is released, so spans still buffered when the
program ends are sent.

<include meta='title="otel_sdk.py"'>../../snippets/observability/otel_sdk.py</include>

In production the processor is usually `BatchSpanProcessor(OTLPSpanExporter())` from
`opentelemetry-exporter-otlp`, with `PeriodicExportingMetricReader(OTLPMetricExporter())` for
metrics.

## Exporting over OTLP

`pyfect.observability` has Effect's own OTLP/HTTP exporters, which need no extra:
`otlp.layer_json(base_url=..., resource=...)` (or `layer_protobuf`) exports logs, metrics and
spans to `/v1/logs`, `/v1/metrics` and `/v1/traces` through the `HttpClient` you provide. Logs
and spans go out in batches every second and every five seconds, or as soon as 1,000 are
waiting; metrics every ten seconds. `otlp_exporter.Flusher` exports everything now, and
releasing the layer sends what is left, waiting up to three seconds.

<include meta='title="otlp_exporters.py"'>../../snippets/observability/otlp_exporters.py</include>

Transient failures are retried three times, honouring a 429's `Retry-After`; any other failure
drops the batch and pauses that exporter for a minute. `otlp.layer_from_config()` reads the
standard `OTEL_*` variables (`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`,
`OTEL_TRACES_EXPORTER=otlp`, ...) and installs nothing unless a signal is switched on.
`otlp_proxy.layer(base_url=..., headers=...)` mounts the same routes on your `HttpRouter` and
forwards browser exports to the collector, adding the credentials on the server.

## Metrics

Metrics are descriptions: `counter`, `gauge`, `histogram`, `summary`, `frequency`, `timer`.
`track`, `track_errors` and `track_duration` update one as an effect ends.

<include meta='title="metrics.py"'>../../snippets/observability/metrics.py</include>

`metric.prometheus_format()` writes the registry in the Prometheus text format for any HTTP
framework to serve. `pyfect.http.prometheus.layer_http()` is that route on `pyfect.http`'s router, at
`/metrics` unless you pass `path=`.

A `timer` records **milliseconds**, as Effect's does, and the Prometheus text leaves out its
`time_unit` attribute, so the name is the only place the unit can show: name a timer
`..._milliseconds` (`checkout_milliseconds_sum 51521` is 51.5 seconds). For Prometheus's
convention of seconds, pass a `histogram` to `track_duration`, which records seconds
(`fx.sleep(0.01).track_duration(metric.histogram("checkout_seconds", boundaries=[1.0]))`).
