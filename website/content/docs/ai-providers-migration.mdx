title: AI providers in 0.7.0
description: "The OpenAI and OpenRouter generated packages follow Effect 4.1.5 in 0.7.0: each renamed or removed schema, type and client method, and what to use instead."
---

`pyfect.ai.openai.generated` and `pyfect.ai.openrouter.generated` are generated from the
`Generated.ts` of Effect's provider packages (`scripts/gen_ai_schemas.py`). Through 0.6.x they
stayed on older releases so a patch release could not rename what you import: OpenAI on Effect
4.1.4's and OpenRouter on 4.1.2's. From 0.7.0 both follow Effect 4.1.5, which regenerated them
from newer OpenAPI specs.

OpenAI keeps every name. OpenRouter's spec renamed or dropped some, and its client gained
operations. The lists below say, for each name that is gone, what took its place.

## What changed for every name

- A schema's type in `types` has the schema's name, so a renamed schema's type is renamed with
  it: `generated.CompletedEvent` became `generated.StreamEventsResponseCompleted`, and
  `types.CompletedEvent` became `types.StreamEventsResponseCompleted`.
- Integer fields (Effect's `Schema.Int`, new in 4.1.5's generator) are typed `int` where they
  were `float`. They decode the same values.
- OpenRouter's `types.ChatToolCall` `id` and `types.ChatStreamToolCall` `index` are
  `NotRequired`, as in Effect: a response may omit them, which decoding has accepted since
  0.6. Read them with `.get("id")` / `.get("index")`, or check `"id" in call`, instead of
  `call["id"]`.
- `Objects_17`, `Arrays_3`, `Union_5` and the types nested in them (`Objects_148__max_price`)
  were Effect's numbered names for schemas the spec left unnamed, and a regeneration numbers
  them afresh. They are listed as removed: the schema is now named, or written where it is
  used. Reach it through the type that holds it (`types.ProviderPreferences`'s `max_price`,
  for example).
- A nested type (`Parent__key`, a struct inside another) is named after its path, so it moves
  when its parent is renamed or its field changes.

pyfect keeps no deprecated aliases for the old names. A schema is a value and a type a
`TypedDict` or alias, and neither can carry `warnings.deprecated` so that pyright reports
their use; an alias that only warned at runtime would hide a rename that pyright now shows
you where the old name is imported.

## How the lists are made

`uv run python scripts/ai_generated_migration.py --write` diffs the packages of 0.6.36 with
0.7.0's. A name that is gone is listed as renamed when exactly one name of 0.7.0 matches it:
a struct with the same fields (descriptions and other annotations aside), else a schema with
the same description, else, for a nested type, the same path under its renamed parent.
Otherwise it is listed as removed: the spec dropped it, or changed it enough that no single
name replaces it. Look up the field that used it in the new type.
