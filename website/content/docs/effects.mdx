An `Effect[A, E, R]` describes a computation. Building one runs nothing; a **run function**
(`run_blocking`, `run_async`, `run_main`) executes it on a fiber.

<include meta='title="values.py"'>../../snippets/effects/values.py</include>

- `fx.succeed(value)` wraps a value; `fx.sync(f)` calls `f` each time the effect runs.
- `map` transforms the value; `flat_map` continues with another effect.

## Generators

Chains of `flat_map` get hard to read. Write the effect as a generator instead: `yield from`
an effect to get its value. `@fx.gen` makes an effect from a generator; `@fx.fn` makes a
function that returns one.

<include meta='title="generators.py"'>../../snippets/effects/generators.py</include>

pyright infers the success type from `return`, the errors from every effect that can fail and
the services from every service used. You rarely write `Effect[...]` yourself, except on
function signatures you want to pin.

A generic function body is the exception: pyright loses its type parameter when the body also
uses other services, so annotate its return as `fx.Gen[A, E, R]` (what the body yields and
returns), as in `def with_scope[R](eff: fx.Effect[int, Never, R]) -> fx.Gen[int, Never, R | Scope]`.
`@fx.fn` raises `TypeError` for a generic body without a return annotation.

pyright widens a literal returned from a lambda: `eff.map(lambda r: r.answers[team].label)` is
an `Effect[str, ...]` even though the label is `Literal["billing", "tech"]`, and the same holds
for `Ok.map`, `fx.for_each` and every other combinator taking a function. A `def` with a return
annotation, or an annotated variable receiving the result, keeps the literal.

## Running effects

| Function | Use it for |
| --- | --- |
| `run_blocking(eff)` | scripts and tests: no event loop needed, sleeps and forks work |
| `run_sync(eff)` | an effect that finishes synchronously; anything else dies with `AsyncFiberError`, as Effect's `runSync` |
| `run_blocking_exit(eff)` | the same, returning an `Exit` (`Success` or `Failure`) instead of raising |
| `await run_async(eff)` | inside asyncio code |
| `run_main(eff)` | a program's entry point: handles SIGINT/SIGTERM, logs failures, sets the exit code |
| `ManagedRuntime.make(layer)` | building services once and running many effects with them (web servers) |

Every run function needs the service type to be `Never`, so a missing service is a type error at
the call site. `run_sync`, `run_blocking` and `run_async` also need the error type to be `Never`; their `_exit`
variants and `run_main` take an effect that can fail and hand you (or log) the failure.

`fx.from_async` and `fx.try_async` wrap coroutines; `fx.blocking` and `fx.try_blocking` move
blocking calls to a thread.
