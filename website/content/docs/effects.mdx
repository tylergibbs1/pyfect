An `Effect[A, E, R]` describes a computation. Building one runs nothing; a **run function**
(`run_blocking`, `run_async`, `run_main`) executes it on a fiber.

<include meta='title="values.py"'>../../snippets/effects/values.py</include>

- `fx.succeed(value)` wraps a value; `fx.sync(f)` calls `f` each time the effect runs.
- `map` transforms the value; `flat_map` continues with another effect.

## Generators

Chains of `flat_map` get hard to read. Write the effect as a generator instead: `yield from`
an effect to get its value. `@fx.gen` makes an effect from a generator; `@fx.fn` makes a
function that returns one. A failure's trace names a plain `@fx.fn` function `at Effect.fn`, as
Effect does; `@fx.fn("check_urls")` names it `at check_urls` and runs each call in a span of
that name (see [Tracing](/docs/observability#tracing)).

<Callout title="A bare number is milliseconds">
As in Effect, `fx.sleep(2.5)` sleeps 2.5 milliseconds, and so does every other duration given as a
number. Write the unit, `fx.sleep("2.5 seconds")`, or a `timedelta`. See
[Durations](/docs/schedules#durations), which shows how to make pyfect warn on every bare number.
</Callout>

pyright infers the success type from `return`, the errors from every effect that can fail and
the services from every service used. You rarely write `Effect[...]` yourself, except on
function signatures you want to pin.

A generic function body is the exception: pyright loses its type parameter when the body also
uses other services, so annotate its return as `fx.Gen[A, E, R]` (what the body yields and
returns), as in `def with_scope[R](eff: fx.Effect[int, Never, R]) -> fx.Gen[int, Never, R | Scope]`.
`@fx.fn` raises `TypeError` for a generic body without a return annotation.

pyright widens a literal returned from a lambda: `eff.map(lambda r: r.answers[team].label)` is
an `Effect[str, ...]` even though the label is `Literal["billing", "tech"]`, and the same holds
for `Ok.map`, `fx.for_each` and every other combinator taking a function. A `def` with a return
annotation, or an annotated variable receiving the result, keeps the literal.

## Running effects

| Function | Use it for |
| --- | --- |
| `run_blocking(eff)` | scripts and tests: no event loop needed, sleeps and forks work |
| `run_sync(eff)` | an effect that finishes synchronously; anything else dies with `AsyncFiberError`, as Effect's `runSync` |
| `run_blocking_exit(eff)` | the same, returning an `Exit` (`Success` or `Failure`) instead of raising |
| `await run_async(eff)` | inside asyncio code |
| `run_main(eff)` | a program's entry point: handles SIGINT/SIGTERM, logs failures, sets the exit code |
| `ManagedRuntime.make(layer)` | building services once and running many effects with them (web servers) |

Every run function needs the service type to be `Never`, so a missing service is a type error at
the call site. `run_sync`, `run_blocking` and `run_async` also need the error type to be `Never`; their `_exit`
variants and `run_main` take an effect that can fail and hand you (or log) the failure.

An effect reads its caller's `contextvars`, as Effect's runs follow Node's `AsyncLocalStorage`:
a request id set by a web request's handler before `await runtime.run_async(...)` is the one the
effect, its forked fibers and its coroutines see, however many requests run at once. A fiber
resumes in the context it waited in, whoever wakes it.

`fx.from_async` and `fx.try_async` wrap coroutines; `fx.blocking` and `fx.try_blocking` move
blocking calls to a thread.

## Common mistakes

These run, or fail far from the line that caused them. Most are what a coroutine would do.

- **`time.sleep` in an effect** blocks the thread, so every fiber of the run waits with it and
  `.timeout` can't interrupt it. Use `fx.sleep("1 second")`, and `fx.blocking(f)` for a blocking
  call you can't avoid: it runs on a thread, and the fiber waits without blocking the others.
  Nothing fails, so to find one, run with `PYFECT_WARN_BLOCKING=100`: a watchdog thread then
  warns with `BlockingStepWarning` (in `pyfect.scheduler`), at the blocking line, about any step
  that runs 100 ms or longer. It is a development tool: off, it starts no thread and the run
  does no extra work. Under `fx.run_async`, asyncio's debug mode (`python -X dev`) also logs
  `Executing <Handle AsyncioScheduler._drain() ...> took 0.302 seconds`, without the line.
- **`run_blocking` in a coroutine or a notebook cell** blocks the running event loop until the
  effect is done, and warns with `RunBlockingInEventLoopWarning`; `run_main` there raises a
  `RuntimeError`, since it starts a loop of its own. There, use `await fx.run_async(eff)`;
  Jupyter runs cells on an event loop, so `await` works at the top of a cell.
- **`yield eff` instead of `yield from eff`** runs the same, but pyright can't see the value or
  the effect's errors and services: the variable is `Unknown`, which strict mode reports. Always
  write `yield from`.
- **Calling a function and using what it gives as the result.** `greet("ada")` builds an
  effect and runs nothing: `print(greet("ada"))` shows `<Effect, not run: ...>`, and
  `greet("ada") + "!"` raises `TypeError`. Run it with `fx.run_blocking(greet("ada"))`, or
  inside a generator, `yield from greet("ada")`.
- **`eff()`** raises `TypeError: '_Succeed' object is not callable` (pyright reports it first):
  an effect is a value, not a function. Run it as above. Python names the effect's internal
  class, so the name varies; [the table below](#calling-or-awaiting-an-effect) lists them.
- **`fx.yield_now` without `()`**: `fx.void` and `fx.never` are effects, but `yield_now` is a
  function that makes one. Write `fx.yield_now().fork()` and `yield from fx.yield_now()`; the
  bare form raises an error that says so.
- **`await eff`** raises `TypeError: '_Succeed' object can't be awaited` (pyright reports it
  first): an effect is a description, not a coroutine. In a coroutine, run it with
  `await fx.run_async(eff)`; inside a generator, `yield from eff`. Effects are deliberately not
  awaitable, so libraries that await whatever is awaitable pass them through untouched. Python
  3.13 words it `object _Succeed can't be used in 'await' expression`.
- **`@fx.fn async def`** is not an effect body: pyright reports that no overload of `fn` matches,
  and running it dies with a `TypeError`. Write a `def` and run the coroutine inside it with
  `yield from fx.from_async(f)`.
- **`eff.catch_tag(...)`** raises `AttributeError`: `catch_tag`, `provide` and the other
  combinators that remove something from the type are functions for `.pipe`:
  `eff.pipe(fx.catch_tag(NotFound, handler))` (see [Typed errors](/docs/errors#handling-errors)).
- **`raise NotFound(...)`** in a generator is a defect, not a typed failure, so `catch_tag` never
  sees it. Fail with `return (yield from NotFound(...))` (see
  [Typed errors](/docs/errors#defining-and-failing)).

### Calling or awaiting an effect

`eff()` and `await eff` fail with Python's own `TypeError`, which names the effect's internal
class. Each message below means the same mistake: the effect was called or awaited instead of
run with `fx.run_blocking(eff)`, `await fx.run_async(eff)`, or `yield from eff` in a generator.

| Made by | `eff()` | `await eff` (Python 3.14) | `await eff` (Python 3.13) |
| --- | --- | --- | --- |
| `fx.succeed`, `fx.void` | `'_Succeed' object is not callable` | `'_Succeed' object can't be awaited` | `object _Succeed can't be used in 'await' expression` |
| `fx.fail` | `'_FailCause' object is not callable` | `'_FailCause' object can't be awaited` | `object _FailCause can't be used in 'await' expression` |
| `fx.sync` | `'_Sync' object is not callable` | `'_Sync' object can't be awaited` | `object _Sync can't be used in 'await' expression` |
| `fx.suspend`, `fx.from_async`, `fx.try_async`, `fx.all` | `'_Suspend' object is not callable` | `'_Suspend' object can't be awaited` | `object _Suspend can't be used in 'await' expression` |
| `fx.gen` | `'_Gen' object is not callable` | `'_Gen' object can't be awaited` | `object _Gen can't be used in 'await' expression` |
| a call of an `@fx.fn` function | `'_Locally' object is not callable` | `'_Locally' object can't be awaited` | `object _Locally can't be used in 'await' expression` |
| `.map` | `'_Map' object is not callable` | `'_Map' object can't be awaited` | `object _Map can't be used in 'await' expression` |
| `.flat_map`, `.as_`, `.tap`, `.timeout`, `.retry`, `fx.blocking` | `'_FlatMap' object is not callable` | `'_FlatMap' object can't be awaited` | `object _FlatMap can't be used in 'await' expression` |
| `.catch_all`, `.catch_cause`, `.catch_if` | `'_MatchCause' object is not callable` | `'_MatchCause' object can't be awaited` | `object _MatchCause can't be used in 'await' expression` |
| `.ensuring`, `.on_exit` | `'_OnExit' object is not callable` | `'_OnExit' object can't be awaited` | `object _OnExit can't be used in 'await' expression` |
| `fx.sleep`, `fx.scoped` | `'_WithFiber' object is not callable` | `'_WithFiber' object can't be awaited` | `object _WithFiber can't be used in 'await' expression` |

## Reading pyright errors

pyright reports most of the mistakes above, but its messages are about types, often several
lines deep. Read an `Effect[A, E, R]` in one as value, errors, services: the third argument is
what still has to be provided.

**A missing service at a run function.** `fx.run_blocking(check())`, where `check` reads
`UrlChecker` that nothing provides:

```text
Argument of type "Effect[int, Never, UrlChecker]" cannot be assigned to parameter "eff"
of type "Effect[A@run_blocking, Never, Never]" in function "run_blocking"
  Type parameter "R_co@Effect" is covariant, but "UrlChecker" is not a subtype of "Never"
```

The run functions take only effects that need nothing (`Never`), and this one still needs
`UrlChecker`. Provide it: `check().pipe(fx.provide(UrlCheckerLive))`.

**A missing service in a `@testing.effect` test.** The same mistake in a test is longer,
because the decorator checks the whole generator:

```text
No overloads for "effect" match the provided arguments
Argument of type "() -> Generator[Effect[Any, Never, UrlChecker] | Effect[Any, Never, Never], ...]"
cannot be assigned to parameter "f" of type "(**P@effect) -> TestBody[Scope]"
  ...
  Type parameter "_YieldT_co@Generator" is covariant, but "Effect[Any, Never, UrlChecker] |
  Effect[Any, Never, Never]" is not a subtype of "Effect[Any, Any, Scope]"
```

Skip to the last line: a test may only yield effects that need at most `Scope`, and one of the
yielded effects needs `UrlChecker`. Provide it inside the test, with `.pipe(fx.provide(Stub))` on
the effect that needs it. The "Untyped function decorator obscures type of function" error on
the same line follows from the first one and goes away with it.

**An `@fx.fn` body that is not a generator.** An `async def`, or a `def` that returns an effect
without any `yield`:

```text
No overloads for "fn" match the provided arguments
Argument of type "(url: str) -> CoroutineType[Any, Any, str]" cannot be assigned to
parameter "f" of type "(**P@fn) -> Generator[Effect[Any, E@fn, R@fn], Any, A@fn]"
```

`fn` takes a generator function. Write a `def` with `yield from`; for a coroutine, use
`yield from fx.from_async(lambda: fetch(url))`, and for a function that only builds an effect,
drop the decorator and return the effect.
