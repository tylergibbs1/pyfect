title: Schema

A schema describes a value once. From it you get a decoder that checks untrusted input and
returns typed data, an encoder back to the wire form, a JSON Schema and Hypothesis strategies.
`pyfect.schema` follows Effect's `Schema`; import it as `S`.

## Decode and encode a payload

`S.Struct(TypedDict)` takes its fields from the TypedDict's annotations: `str`, `int`, `float`,
`bool`, `None`, `bytes`, `Duration`, enums, literals, unions, TypedDicts, schema classes and
the standard containers (`list`, `tuple`, `dict`, `frozenset`, `Sequence`, `Mapping`) and
pyfect's `HashSet` / `HashMap` of these.
A `datetime` has two schemas (`S.DateTimeUtc`, `S.DateTimeZoned`), so give it one. Keyword
arguments give a field a stricter schema, such as a checked `S.Int`. That schema must decode to
the key's type: `quantity=S.String` for `quantity: int` is a `TypeError` when the struct is
made.

A check can also live in the annotation: `Annotated[int, S.is_between(minimum=1, maximum=99)]`
is an `S.Int` with that check, in a TypedDict, a schema class, a container (`list[...]`) or a
`type` alias. The checks run when decoding and when constructing a class. Metadata that is
neither a check nor a schema is ignored, and a keyword argument or `S.field(schema)` replaces
the annotation's schema.

The metadata can carry the schema itself: `Annotated[int, S.Int.check(S.is_greater_than(0))]`,
or a codec such as `Annotated[float, S.FiniteFromString]`, as a pydantic model reads it. That
schema is used in place of the one the type would give, so the type needs no schema of its own,
and the checks beside it refine it. With several schemas in the metadata the last one wins, and
a keyword argument or `S.field(schema)` still wins over the whole annotation. Pyright cannot see
metadata, so it does not check that the schema decodes to the annotation's type; `S.field`
is the form it checks.

Each decoder and encoder comes in several forms: `_sync` raises, `_result` and `_exit` return
the outcome, `_effect` fails in the error channel. `decode_unknown_*` accepts any input, while
`decode_*` expects the encoded type. They all take parse options such as `errors="all"`.

`S.to_codec_json(schema)` reads and writes JSON values, so its encoded type is `JsonValue`
whatever the schema, as Effect types it `Json`: the struct's fields are not part of the type.
Encoding gives each array as the container its schema decodes to, a `tuple` for `S.Array`
(Effect's readonly array) and a `list` for `S.List` (Effect's mutable one). Both are JSON
arrays, so they write the same JSON text and compare alike in `json_patch.get`.

`S.Record(key, value)` decodes a dict whose keys match `key`. As in Effect, a key that fails the
key schema is not reported with that schema's message: it is an excess property, which is dropped
unless you pass `on_excess_property="error"`.

## Sets and maps

`S.FrozenSet(item)` and `S.Map(key, value)` decode to a `frozenset` and a `dict`. Python's
containers treat `True` as `1`, where Effect keeps them apart, so these refuse input that would
merge them. `S.HashSet(item)` and `S.HashMap(key, value)` decode to pyfect's `HashSet` and
`HashMap`, which compare as Effect's `Equal` does: `1` and `True` are two items and every
`NaN` is one. In JSON, a set is a list of its items and a map a list of `[key, value]` pairs,
in the order Effect writes them. Annotations work too: a `HashSet[int]` field is
`S.HashSet(S.Int)`.

## Classes

A subclass of `S.Class` is an immutable class with a keyword constructor, and a schema. Its annotations are its
fields, `S.field(schema)` gives a field its own schema, and a default makes the key optional.
The constructor checks every field; `S.new(User, disable_checks=True)(...)` builds one without
running the checks (Effect's `new User(props, { disableChecks: true })`), still checking the
fields' types.
`S.from_json_string` wraps any schema so it reads and writes JSON text. A class whose
fields differ between the database and a JSON API is a [model](/docs/models).

A default fills a missing key when decoding, but the field's schema still has to take the
default when the class is built or encoded. So `S.field(S.Int, default=None)` decodes
`{}` and then fails on that `None`. A field that may be `None` needs a schema that accepts
it: `S.Union(S.Int, S.Undefined)` leaves the key out while the value is `None`, and
`S.NullOr(S.Int)` writes `null`.

## Unions

`S.TaggedClass` adds a `"_tag"` key, and `S.TaggedUnion` uses it to pick the member, so an
error message talks about one member rather than all of them. The decoded value is a plain
Python union, so `match` on it and pyright checks that every case is handled. `S.Union`

## Branded values

A slug and an account code are both strings, but a function taking one should refuse the
other. Declare each as a `typing.NewType`: pyright tells them apart and at run time they are
plain strings. `S.refine(guard)` takes a guard returning `TypeIs[Brand]` and narrows the
schema's type to the brand, failing with `Expected <expected>` when the guard says no; it is
Effect's `refine` with a refinement. `S.from_brand(brand)` runs the checks of a
[`Brand`](/docs/reference/brand) instead, so the schema and the brand's constructor check the
same things. A TypedDict field of the branded type then takes that schema as its keyword.

## Transformations

A codec decodes one type from another: `NumberFromString`, `Trim`, `DateTimeUtcFromString`,
`BytesFromBase64` and so on. `S.decode_to(target, transformation)` builds your own codec
from a function each way, and codecs compose inside structs and classes.

`S.to_type(schema)` and `S.to_encoded(schema)` give a codec's two sides as schemas of their
own. A check on a struct, array or union carries over to the other side when none of its
parts transforms; when one does, only checks of the shape (a length, a size, a key count)
carry over, since the parts' values differ.

## JSON nesting limit

pyfect reads JSON text nested at most 512 arrays and objects deep. Deeper text is refused
before it is parsed, and brackets inside strings don't count. This is a deliberate difference
from Effect, whose `JSON.parse` reads any depth: Python's `json.loads` reads about a hundred
thousand levels, and code that walks such a value with plain recursion (`==`, `repr`, a
reviver) then raises `RecursionError`.

Every JSON parse in pyfect goes through this check, and the refusal is the error malformed
JSON gets at that entry point:

- `S.from_json_string`, `S.UnknownFromJsonString` and config values read through them: a
  `SchemaError`.
- `HttpServerRequest.json`, `schema_json`, `schema_body_json` and HttpApi JSON payloads: a 400.
- HTTP client response bodies, persistence, cluster message storage, workflows and the SQL
  drivers: the error each one gives malformed JSON.
- RPC frames: a `ValueError` from `serialization.json` and `json_rpc()`, an
  `NdjsonDecodeError` from `serialization.ndjson` and `nd_json_rpc()`.
- `ndjson` decoders: a failure with reason `"InvalidJson"`.
- AI provider responses and stream events, tool call parameters (a
  `ToolParameterValidationError`) and MCP messages (a parse error).
- The chat adapters for Teams (128 levels), Discord, Telegram and WhatsApp (64) stop sooner.

`json_array.decode()` and `decode_string()` take their own `max_depth` (1000 by default) and
fail with kind `"Limit"`. `jsonc.parse` and `json5.parse` have no limit, as in Effect: their
parser keeps its own stack, so it reads any depth without recursion.

An app that wraps parsed JSON in envelopes of its own before writing it again (an outbox row
holding an event, a job holding a request) adds a level per envelope, and the limit applies
when the outer text is read back. A record 511 levels deep, wrapped twice, is 513 deep and no
longer reads. Leave headroom by refusing input at your edge a few levels below 512, for
example with a schema whose nesting is bounded.

## JSON Schema

`S.to_json_schema_document(schema)` describes the JSON that `S.to_codec_json(schema)` reads
and writes, in draft 2020-12. Checks become keywords where JSON Schema has one. `S.is_pattern`
takes a Python `re` pattern, which JSON Schema's ECMAScript `pattern` can't carry, so it writes
none; `S.is_ecma_pattern` (Effect's `isPattern`) checks with the ECMAScript pattern and writes it.
`pyfect.json_schema` converts documents to draft-07, draft-04 and OpenAPI.
`pyfect.schema.representation.from_json_schema_document` goes the other way: it turns a
JSON Schema document into a schema that validates, and `to_code_document` writes the Python
source of a schema, with `to_code_module` laying it out as a module.

## Compiled decoders

`pyfect.schema.jit_compiler.enable(schema.ast)` (a schema class's is `User.ast`) generates
Python source for the schema's validators the first time each one is used, compiles it, and installs it in the registry every
parser shares (`S.decode_unknown_sync`, `S.is_`, `S.make`, ...). Importing
`pyfect.schema.jit_compiler.install` does that for every schema. A compiled decoder gives the
interpreter's results and issues: when its fast check fails, the interpreter reports why.
`pyfect.schema.aot_compiler.compile(targets)` writes the same code as a module ahead of time, and
`aot_compiler.build.build(...)` writes one that installs itself, so nothing is generated at run
time. On a nested struct with ten rows the compiled decoder is about six times faster; an invalid input costs more, since the interpreter then runs to report the issue.

## Standard Schema

`S.to_standard_schema_v1(schema)` adds the Standard Schema interface at the spec's `~standard`
key (`getattr(adapted, "~standard")`, typed as `adapted.__standard__`): `version`, `vendor` and
`validate(value, options=None)`, which returns `{"value": ...}` or `{"issues": [...]}` (an
awaitable of it when decoding has to wait). `S.to_standard_json_schema_v1(schema)` adds
`json_schema.input({"target": ...})` and `json_schema.output(...)` for `"draft-2020-12"` and
`"draft-07"`. The adapter is still the schema: it decodes, constructs and subclasses as the
schema does.
