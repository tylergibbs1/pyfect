title: Platform

Programs reach the operating system through services: `FileSystem` and `Path` for files,
`ChildProcessSpawner` for processes, `HttpClient` for HTTP. Your code asks for the service and
the layer you provide decides what answers, so a test can swap the network or the disk for a
stand-in. Every file and process operation fails with a typed `PlatformError` whose reason
says what went wrong (`NotFound`, `PermissionDenied`, `AlreadyExists`, ...).

## Files

`fs.read_file_string` and `fs.write_file_string` read and write a whole file; `fs.stream`
reads one as a stream of byte chunks, so memory stays bounded however large it is, and
`fs.sink` writes one from a stream. `make_temp_directory_scoped` gives a directory that is
removed, with everything in it, when its scope closes.

## Child processes

`process.make(command, args)` describes a process. Running it in a scope starts the process
and gives a handle whose `stdout` and `stderr` are byte streams and whose `stdin` is a sink.
When the scope closes, a process still running is killed. The spawner's `string`, `lines`
and `stream_lines` start a command, read its output and clean up in one call.

## HTTP requests

An `HttpClient` is a value: methods like `filter_status_ok`, `retry_transient` and `transform`
each give back a new client. `retry_transient` retries timeouts, transport errors and the
statuses worth retrying (408, 429, 500, 502, 503 and 504), and waits at least as long as a
response's `Retry-After` asks. `response.schema_body_json` decodes the body with a
[schema](/docs/schema), so a payload of the wrong shape fails with a `SchemaError`.

This program runs against `client.layer_test`, which answers each request with a function.
In production, provide `httpx_client.layer` instead (install the `pyfect-dev[httpx]` extra).

## HTTP client errors

Every failure of a request is an `HttpClientError` whose `reason` says what went wrong:
`TransportError` (the request couldn't be sent or its response received), `EncodeError`,
`InvalidUrlError`, `StatusCodeError`, `DecodeError` or `EmptyBodyError`.
`fx.catch_reason(HttpClientError, StatusCodeError, f)` recovers from one of them. The
reason's `cause` is the underlying exception, such as a refused connection or a client used
after the scope that owned it closed. `error.message` is Effect's text and leaves the cause
out; `str(error)` adds it when the reason has no description of its own.

is virtual, so a test of a five-second timeout finishes at once.
