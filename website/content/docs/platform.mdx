Programs reach the operating system through services: `FileSystem` and `Path` for files,
`ChildProcessSpawner` for processes, `HttpClient` for HTTP. Your code asks for the service and
the layer you provide decides what answers, so a test can swap the network or the disk for a
stand-in. Every file and process operation fails with a typed `PlatformError` whose reason
says what went wrong (`NotFound`, `PermissionDenied`, `AlreadyExists`, ...).

## Files

`fs.read_file_string` and `fs.write_file_string` read and write a whole file; `fs.stream`
reads one as a stream of byte chunks, so memory stays bounded however large it is, and
`fs.sink` writes one from a stream. `make_temp_directory_scoped` gives a directory that is
removed, with everything in it, when its scope closes. `fs.glob` finds the paths under a
root that match a pattern (`**` crosses directories, `{a,b}` and `[a-z]` choose, `dot=True`
includes names starting with `.`); `pyfect.glob` matches the same patterns against a path
string.

`Path` joins, resolves and splits paths with the rules of Node's `path` module:
`path.posix` and `path.win32` give what Node's `path.posix` and `path.win32` give, on any host
(checked against every case in Node's own path tests), so `path.layer_win32` runs a program
under Windows path rules on macOS or Linux. `resolve` on Windows rules uses the drive's own
working directory (the `=C:` variable), as Node does.

These programs run with `fx.run_main` rather than `run_blocking`, which only takes effects that
cannot fail: `run_main` logs a failure and exits the process with a nonzero status.

## Child processes

`process.make(command, args)` describes a process. Running it in a scope starts the process
and gives a handle whose `stdout` and `stderr` are byte streams and whose `stdin` is a sink.
As in Node, `stdin` closes as soon as the process exits, and a write still in progress then
fails. When the scope closes, a process still running is killed. The spawner's `string`, `lines`
and `stream_lines` start a command, read its output and clean up in one call.

## HTTP requests

An `HttpClient` is a value: methods like `filter_status_ok`, `retry_transient` and `transform`
each give back a new client. `retry_transient` retries timeouts, transport errors and the
statuses worth retrying (408, 429, 500, 502, 503 and 504), and waits at least as long as a
response's `Retry-After` asks. `timeout` fails a request that gets no response in time with a
`TransportError` (so `retry_transient` retries it); applied before `retry_transient` each
attempt gets its own budget, applied after it the budget covers every attempt.
`client.is_transient_error` and `client.is_transient_response` classify failures the same way
for a policy of your own. `response.schema_body_json` decodes the body with a
[schema](/docs/schema), so a payload of the wrong shape fails with a `SchemaError`.

This program runs against `client.layer_test`, which answers each request with a function.
In production, provide `httpx_client.layer` instead (install the `pyfect-dev[httpx]` extra).

Every request runs in a client span and sends trace headers (see
[observability](/docs/observability)); interrupting a request aborts it.

A body is sent as it is pulled when it is a stream (`body.stream`), and so is a form file
whose content is a function opening a stream (`body.File(lambda: chunks, "big.bin")`): the
file is read only as fast as the connection takes it, and an interrupted request stops it.

`with_cookies_ref(ref)` keeps the cookies responses set in a `Ref[tuple[Cookie, ...]]` and
sends them back the way a browser does (RFC 6265): only to the host that set them, or the
hosts their `Domain` covers, on their `Path`, over https when they're `Secure`, and not after
they expire. `cookies.merge_into_array` and `cookies.to_request_cookie_header` are the same
rules on a plain tuple, for seeding a jar or reading one.

## URLs

`fx.Url` is JavaScript's `URL` as an immutable Python value: `fx.Url(text, base)` parses
and normalizes as the WHATWG URL Standard says (the same results as Node on the
web-platform-tests suite, international domain names included), and raises `ValueError`
for text that isn't a URL; `fx.Url.parse` gives `None` instead and `fx.Url.can_parse`
asks. It has `URL`'s getters (`href`, `origin`, `host`, `pathname`, `search`, `hash`,
`search_params`, ...), and two URLs are equal when their `href` is. `str(url)` is the
`href`. `pyfect.http.url` has Effect's `Url` functions: `set_port`, `set_search`,
`set_url_params` and the other setters give a new `Url`, as `URL`'s setters would change
the old one, and `mutate` hands a function a mutable copy. `config.url`, the `URL`
schemas, request URLs and `Path.to_file_url` / `from_file_url` all use `Url`.

## HTTP client errors

Every failure of a request is an `HttpClientError` whose `reason` says what went wrong:
`TransportError` (the request couldn't be sent or its response received), `EncodeError`,
`InvalidUrlError`, `StatusCodeError`, `DecodeError` or `EmptyBodyError`.
`fx.catch_reason(HttpClientError, StatusCodeError, f)` recovers from one of them. The
reason's `cause` is the underlying exception, such as a refused connection or a client used
after the scope that owned it closed. `error.message` is Effect's text and leaves the cause
out; `str(error)` adds it when the reason has no description of its own.
