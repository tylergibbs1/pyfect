`pyfect.ai` follows Effect's `effect/ai`. A program asks the `LanguageModel` service for
text, a decoded object or a stream, and a provider's layer supplies the service. So the
same program runs on Claude, on any OpenAI-compatible API, or on a scripted model in a
test. Failures are an `AiError` whose `reason` says what went wrong (a rate limit, an
invalid request, output that does not match its schema).

## Language models and providers

`language_model.generate_text(prompt)` needs a `LanguageModel` and gives a
`GenerateTextResponse`: its `content` parts, with `text`, `tool_calls`, `tool_results`,
`finish_reason` and `usage`. A prompt is a string, a list of messages or a `Prompt`.

`pyfect.ai.anthropic` calls Anthropic's Messages API and `pyfect.ai.openai_compat` any
Chat Completions API (OpenAI, a local server, a gateway). Each has a `client` layer, with
the API key as a `Redacted` (or from `Config` with `layer_config`), and a `language_model`
whose `model(name).layer` provides the `LanguageModel`. Both send their requests through
the [`HttpClient`](/docs/platform) service, so they need no vendor SDK: provide
`httpx_client.layer` (the `pyfect-dev[httpx]` extra) in production, or a test client, as here.

`language_model.make(generate_text=..., stream_text=...)` builds a `LanguageModel` from two
functions of a request's `ProviderOptions` (its prompt, tools and response format). The
examples below use it to script the model's answers, as a test does.

## Tools and toolkits

`tool.make(name, parameters=..., success=..., failure=...)` declares a tool; the model
sees its description and its parameters' JSON Schema. `toolkit.make(*tools)` groups tools,
and `to_layer(*handlers)` provides their handlers: pyright checks `GetWeather.handler(f)`
against the tool's schemas and the services it declares in `dependencies`.

With `toolkit=Tools`, `generate_text` offers the tools, decodes each call's parameters,
runs its handler and adds the results to the response. A handler's failure fails
`generate_text`, or, for a tool made with `failure_mode="return"`, goes back to the model
as a failure result. `tool_choice` is `"auto"`, `"none"`, `"required"`, `{"tool": name}` or
`{"one_of": names}`, and a tool with `needs_approval` gives an approval request in place
of running.

## Structured output

`language_model.generate_object(prompt, schema=...)` asks for JSON matching a
[schema](/docs/schema) and decodes it into `value`, typed by the schema. The provider gets
the schema's JSON Schema, named `object_name`; output that does not decode fails with an
`AiError`.

## Streaming

`language_model.stream_text(prompt)` is a [stream](/docs/streams) of the response's
parts as they arrive: text, reasoning and tool-parameter deltas, tool calls, then their
results, then the finish part. With a toolkit, each handler starts as soon as the stream
moves past its call.

## Conversations

A conversation is a `Prompt` that grows: `concat` adds the next user message, and
`prompt.from_response_parts(reply.content)` turns a reply, with its tool calls and
results, into the messages that continue it. `set_system` replaces the system message.

`pyfect.ai.chat` does this for you. A chat (`chat.empty`, `chat.from_prompt(prompt)`)
has the same `generate_text`, `generate_object` and `stream_text`; each call sends the
history plus the new prompt and adds the reply, and calls on one chat run one at a time.
`export_json` and `chat.from_json` save and restore a history. `chat.Persistence`, from
`chat.layer_persisted(store_id=...)` over any [persistence](/docs/persistence) backing
store, keeps chats by id: `get_or_create(id, time_to_live=...)` opens one and every call
saves it.

An `EmbeddingModel`'s `embed(text)` and `embed_many(texts)` give vectors, and
concurrent `embed` calls are sent as one batch;
`openai_compat.embedding_model.model(name, dimensions=n).layer` provides one. Each call
runs in a span, such as `LanguageModel.generateText`, that
[tracing](/docs/observability) records.
