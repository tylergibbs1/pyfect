pyfect needs Python 3.13 or newer; its one dependency is `typing-extensions`. Install it from
PyPI: the distribution is named `pyfect-dev` and you import `pyfect`.
The PyPI package called `pyfect` is an unrelated project.

<InstallCommand
  uv={"uv init --python 3.14+gil app && cd app\nuv add pyfect-dev\nuv add --dev pyright"}
  pip={"mkdir app && cd app\npython3.13 -m venv .venv && . .venv/bin/activate\npip install pyfect-dev pyright"}
/>

These start a new project in `app/`. `--python 3.14+gil` asks for the standard build of CPython
3.14; it needs uv 0.9.8 or later, and an older uv says
`No interpreter found for executable name '3.14+gil'` (update it with `uv self update`, or
`brew upgrade uv` for Homebrew's). A plain `--python 3.14` lets uv pick the free-threaded
3.14t, where some libraries publish no wheels yet (`psycopg[binary]` is one), and it does
whenever it finds one installed first. The pip commands name `python3.13` because a plain
`python3` is often older: on macOS, `/usr/bin/python3` is Python 3.9. Any newer Python works
too, so use `python3.14` if that is the one you have. With a Python older than
3.13, pip finds no release it can install and says only:

```text
ERROR: Could not find a version that satisfies the requirement pyfect-dev (from versions: none)
ERROR: No matching distribution found for pyfect-dev
```

Check with `python3 --version`, and if it is older than 3.13, install a newer one (from
python.org, `brew install python@3.13`, or `uv python install 3.13`) and make the virtual
environment with it. In a project you already have, `uv add pyfect-dev` (or
`pip install pyfect-dev`) is enough, as long as its `pyproject.toml` has a `[project]` table:
uv adds dependencies there and refuses a file that only configures tools.

Extras add integrations: `otel` (OpenTelemetry, `pyfect.otel`), `hypothesis`, `pydantic` and
`msgspec` ([Pydantic and msgspec](/docs/pydantic-msgspec)), `httpx` (the HTTP client backend),
`websockets` (WebSocket clients and servers), `server` (the uvicorn HTTP server), `http2` (the
HTTP/2 server on hypercorn), `pg` (PostgreSQL on psycopg), `mysql` (MySQL on asyncmy), `mssql`
(SQL Server on python-tds), `redis` (Redis on redis-py), `crypto` ([cryptography and
JOSE](/docs/crypto), on cryptography), `eventlog` (event log encryption, on cryptography),
`brotli` (`br` response compression, on brotlicffi), `regex` (more ECMAScript patterns in
schemas) and `watch` ([`FileSystem.watch`](/docs/platform) on the operating system's change
notification, on watchfiles). For example:

<InstallCommand
  uv='uv add "pyfect-dev[otel]"'
  pip='pip install "pyfect-dev[otel]"'
/>

Importing a module whose extra is missing raises an `ImportError` with the commands that install it,
for uv and for pip.
When the extra is installed but its library fails to import, the `ImportError` shows that
library's own error instead: psycopg, for one, needs the libpq C library, which slim Docker
images such as `python:3.14-slim` leave out. Install it with the system's package manager
(`apt-get install libpq5`) or add `psycopg[binary]`, which bundles it (psycopg publishes no
binary build for free-threaded Python, so on 3.14t install libpq).

### Free-threaded Python

Every extra keeps the GIL off on a free-threaded CPython (3.14t). The `brotli` extra installs
brotlicffi rather than Google's `brotli` package, whose C module turns the GIL back on for the
whole process when it is imported, and httpx imports it whenever it is installed. If another
dependency pulls in `brotli`, httpx loads that one instead; check with
`python -W error::RuntimeWarning -c "import httpx"`, which fails if a module enabled the GIL.

## Type checking

pyright is the type checker pyfect is built for; its inference is what makes errors and services
part of the type. Use strict mode, with one setting turned off: pyright infers an unannotated
generator's send type as `Unknown` ([pyright#10279](https://github.com/microsoft/pyright/issues/10279)),
and effect generators never use it.

```toml title="pyproject.toml"
[tool.pyright]
typeCheckingMode = "strict"
reportUnknownParameterType = false
```

`uv init` made `pyproject.toml` for you; add these lines to it. The pip commands made no
`pyproject.toml`, so create one in `app/` with just these lines. Without it, pyright runs in
its default mode and misses the errors strict mode reports.

## Check it works

Save this as `hello.py` and run it with `uv run python hello.py` (or `python hello.py`), then
`uv run pyright hello.py` (or `pyright hello.py`) to type check it.
