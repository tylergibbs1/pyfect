pyfect needs Python 3.13 or newer; its one dependency is `typing-extensions`. Install it from
PyPI: the distribution is named `pyfect-dev` and you import `pyfect`.
The PyPI package called `pyfect` is an unrelated project.

<InstallCommand
  uv="uv add pyfect-dev"
  pip="pip install pyfect-dev"
/>

Extras add integrations: `otel` (OpenTelemetry, `pyfect.otel`), `hypothesis`, `pydantic` and
`msgspec` ([Pydantic and msgspec](/docs/pydantic-msgspec)), `httpx` (the HTTP client backend), `websockets`, `server` (the uvicorn HTTP server),
`http2` (the HTTP/2 server on hypercorn), `pg` (PostgreSQL on psycopg), `mysql`, `mssql`, `redis`, `crypto` ([cryptography and JOSE](/docs/crypto)), `eventlog` (event log encryption), `brotli` (`br`
response compression, on brotlicffi), `intl` (`Intl`-style date formatting on babel), `regex` (more ECMAScript patterns in schemas) and `watch` ([`FileSystem.watch`](/docs/platform) on the operating system's change notification, on watchfiles). For example:

<InstallCommand
  uv='uv add "pyfect-dev[otel]"'
  pip='pip install "pyfect-dev[otel]"'
/>

Importing a module whose extra is missing raises an `ImportError` with the command that installs it.
When the extra is installed but its library fails to import, the `ImportError` shows that
library's own error instead: psycopg, for one, needs the libpq C library, which slim Docker
images such as `python:3.14-slim` leave out. Install it with the system's package manager
(`apt-get install libpq5`) or add `psycopg[binary]`, which bundles it (psycopg publishes no
binary build for free-threaded Python, so on 3.14t install libpq).

### Free-threaded Python

Every extra keeps the GIL off on a free-threaded CPython (3.14t). The `brotli` extra installs
brotlicffi rather than Google's `brotli` package, whose C module turns the GIL back on for the
whole process when it is imported, and httpx imports it whenever it is installed. If another
dependency pulls in `brotli`, httpx loads that one instead; check with
`python -W error::RuntimeWarning -c "import httpx"`, which fails if a module enabled the GIL.

## Type checking

pyright is the type checker pyfect is built for; its inference is what makes errors and services
part of the type. Use strict mode, with one setting turned off: pyright infers an unannotated
generator's send type as `Unknown` ([pyright#10279](https://github.com/microsoft/pyright/issues/10279)),
and effect generators never use it.

```toml title="pyproject.toml"
[tool.pyright]
typeCheckingMode = "strict"
reportUnknownParameterType = false
```
