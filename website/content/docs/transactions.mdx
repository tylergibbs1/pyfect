`fx.tx(eff)` runs `eff` as a transaction. It reads and writes `TxRef`s through a journal,
then commits every write at once. If another fiber changed a ref the transaction read before
it could commit, the body runs again. No lock is held while a body runs (checking and
committing take a process-wide lock for an instant), so transactions don't deadlock and
compose freely: a `tx` inside another `tx` joins the outer one.

## TxRef

A `TxRef[A]` is a mutable cell. `get`, `set`, `update` and `modify` join the running
transaction, or run as a transaction of their own when there is none.

The body can run more than once, so keep side effects other than `Tx*` operations, such as
logging or requests, outside `tx`.

## Waiting with tx_retry

`fx.tx_retry` abandons the current attempt and waits until another transaction commits to one
of the refs this one read, then runs the body again. This is how you wait for a
condition, with no polling and no condition variables.

## A bank transfer

A transfer deposits into one account and withdraws from another. A typed failure inside `tx`
discards every write the transaction made, so a failed withdrawal undoes the deposit before
it. Two hundred transfers run concurrently, and the total balance stays the same.

## Sharing refs between runs

`TxRef`s, and every transactional collection below, can live at module level and be used by
runs on several threads at once, such as `fx.run_blocking` calls from the threads of a web
server (see [Threads](/docs/threads#sharing-state-between-runs)). Commits from every run go
one at a time, so a transaction never commits over a write it did not see, and a fiber
waiting in `tx_retry` in one run wakes when a run on another thread commits to a ref it read.

## Catching a failure inside tx

A transaction has no savepoints. The writes are undone only when the whole `tx` fails. A
failure caught inside `tx` leaves the transaction running, and every write made before it,
including those of the effect that failed, commits with the rest. Effect behaves the same.
To undo a step's writes, catch its failure outside `tx`, or check before writing.

## Transactional collections

`TxQueue`, `TxHashMap`, `TxHashSet`, `TxChunk`, `TxPriorityQueue`, `TxPubSub`,
`TxSemaphore`, `TxReentrantLock`, `TxDeferred` and `TxSubscriptionRef` are built on `TxRef`,
so they can all take part in the same transaction. A `take` from an empty queue, or an
`offer` to a full bounded one, waits through `tx_retry`.

## Coordinating fibers

The transactional versions of `Deferred`, `Semaphore` and a read/write lock wait through
`tx_retry`, so they compose with other refs in one transaction. `TxDeferred.wait()` waits
until the deferred is completed with `succeed`, `fail` or `done(result)`.
`TxSemaphore.make(n)` hands out `n` permits: `with_permit(eff)` holds one while `eff` runs,
and `acquire`, `release` and `try_acquire` work inside a larger `tx`. A `TxReentrantLock`
lets any number of fibers hold a read lock (`with_read_lock`) while no fiber holds the write
lock (`with_write_lock`); a fiber can take a lock it already holds.

A `TxPubSub` gives each subscriber its own `TxQueue` for as long as its scope lasts
(`subscribe()`), and `publish` offers a value to all of them in the running transaction, so
a transaction that rolls back publishes nothing. `bounded`, `dropping`, `sliding` and
`unbounded` choose what happens when a subscriber's queue is full, as for `PubSub`. A
`TxSubscriptionRef` is a `TxRef` that publishes every value it stores: `changes()` is a
queue of the current value and then each committed one, and `changes_stream()` the same as a
`Stream`.
