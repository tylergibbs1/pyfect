Every effect runs on a **fiber**, a lightweight thread on pyfect's scheduler. The same program
runs with `run_blocking` (no event loop) or on asyncio with `run_async`.

## Running effects concurrently

`fx.for_each` and `fx.all` take a `concurrency` limit (a number or `"unbounded"`; sequential by
default). The first failure interrupts the others.

## Fibers

`eff.fork()` starts a child fiber. `join` waits for its result, `interrupt` stops it and waits
for its finalizers. A fiber's children are interrupted when it finishes, so forked work never
outlives the code that started it (`fork_daemon` opts out).

<Diagram name="fiber-tree" title="Fibers form a tree: each fork adds a child, and interruption flows from a fiber to its children" />

Interruption is not an exception you can catch: handlers like `catch_all` don't see it, and
`on_interrupt`, `ensuring` and scope finalizers always run. Code that must not be interrupted
halfway goes in `fx.uninterruptible_mask`.

## Races and timeouts

`race`, `race_all` and `timeout` always wait for the losers to finish cleaning up before
returning.

## Fiber sets

A `FiberSet` holds fibers that live as long as a scope: each one leaves the set when it
completes, and those still running are interrupted when the scope closes. `join` fails with
the first failure of a fiber in the set. Give the set its fibers' success and error types,
`FiberSet[A, E].make()`: a bare `FiberSet.make()` is a `FiberSet[object, object]`, and its
`join` fails with `object`. `FiberMap` and `FiberHandle` key their fibers, or hold one.

## Limits per key

A `Semaphore` caps how many fibers run a section at once. A `PartitionedSemaphore[K]` is one
pool of permits shared by keys, such as hosts: each fiber waits in its key's line, and freed
permits go round-robin across the keys, so a key with many waiters can't starve the others.

## Publishing to every subscriber

A `PubSub` delivers each message to every subscription. What it does when `capacity`
messages are unread is a strategy: `bounded` makes publishers wait for the slowest
subscriber, `dropping` drops the new message, `sliding` drops the oldest. `PubSub.make`
takes the store and any strategy, including your own: `BackPressureStrategy`,
`DroppingStrategy` and `SlidingStrategy` implement `pubsub.Strategy`, Effect's five hooks
(`handle_surplus` for a publish that does not fit, `complete_pollers_unsafe` to give
messages to parked takes, and so on), and `"suspend"`, `"dropping"` and `"sliding"` name
them. A strategy gives a parked take its message with `poller.succeed(message)`: the take
collects it when it resumes, and if it is interrupted first, the message goes back to its
subscription.
