# Test files that read the clock themselves (tests/test_timing_guard.py), with their read count.
# A line is `path reads  # reason` (tests/_inventory.py): the reason names the real time the
# file measures and why the TestClock cannot drive it.
_leaked_fibers.py 6  # the background scheduler's timers are due on the real time.monotonic clock: the background thread gets 0.5 s to run what is queued and a file's timers due within 0.5 s get to fire before it is reported, and the report says when each is due; the TestClock never drives that scheduler
_native_stacks.py 4  # the capture's deadline for the tools it runs against the real hung process, and the real-time window it ran in, which the stall watchdog leaves out of the stalls it reports; a capture is real time the TestClock never sees
_stalls.py 25  # the stall watchdog (with time.time for when its alarms are due and when each sample was taken) measures how long the real process went without running (tick gaps, process CPU, GC passes, the test thread's samples and CPU for a timeout with no stall, and the host freezes a test's timeout leaves out, and a passed test's running time against its limit); a stall is real time the TestClock never sees
free_threaded/stress.py 2  # the register race's time budget: past its fixed rounds it runs more until 10 s have passed, so a loaded machine (each round a thread start and a cross-thread wake) runs fewer rounds instead of outrunning the test's limit; nothing is asserted on the time
oracle/_docker.py 2  # deadline for a Docker container (SQL Server, MySQL, ClickHouse, libSQL, Redis) to serve; the server runs on real time in another process
